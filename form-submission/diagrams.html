Gate10 ER図

実装済みのデータ構造　｜　1＝親1件、N＝子0件以上　｜　PK＝主キー、FK＝外部キー、UK＝一意

USERS 利用者

PK id
name / role
UK login
salt / hash

DEALS 案件

PK id / FK owner
customer / title
stage / action / due
amount（NULL可）
expected（NULL可）
memo / updated
version / won_at

HISTORY 更新履歴

PK id / FK deal, actor
at / version
before_json / after_json

FEEDBACK 既読・反応

複合PK (deal, version)
FK deal / reader
read_at / reaction
reacted_at

AUDIT ログイン記録

PK id / at
login / success
存在しないIDの失敗も記録

既読・反応は案件の版ごとに保持し、営業が更新すると新しい版は未確認になる。案件更新と履歴を同一トランザクションで保存。
AUDITには外部キーを設けない。顧客マスタと管理者用マスタは今回未作成。セッションはプロセス内管理でDBテーブルではない。

Gate10 画面遷移図

営業の更新から部長の反応まで　｜　実装済み画面と、今回描いていない画面を区別

ログイン役割に応じて移動
自分の案件一覧営業：本人の案件のみ
案件登録空欄から入力
営業の案件詳細反応と変更履歴を確認
案件更新前回値を表示して保存
全体ダッシュボード部長：全案件・見込み・要注意
部長の案件詳細開くと現在版を既読に記録
同じ詳細画面で反応営業の次回表示に反映
描かなかった画面・今回の対象外：管理者の利用者管理、選択肢設定、担当者付替え、Excel取込、通知設定、週次レポート。中核機能の実装を優先し、本番基盤や運用の確定後に検討する。
登録・更新は共通フォーム。ログアウトは全画面から可能。入力エラーはフォーム内表示。通信中は保存ボタンを無効化。承認待ちによる更新の制限は設けない。
