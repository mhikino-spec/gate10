Gate10 設計図と画面下書き

営業の更新 → 部長の確認と反応 → 営業の次の行動、という循環を最小の操作で実現する。

ER図の概要

USERS 利用者PK id
name / role / login
salt / hash
DEALS 案件PK id / FK owner
顧客・案件・ステージ
行動・期日・金額・予定日
更新日時 / version
HISTORY 変更履歴PK id / FK deal, actor
日時 / version
before_json / after_json
FEEDBACK 既読と反応PK deal + version
FK reader
既読日時 / 反応 / 反応日時
USERS 1 ── N DEALS　（担当）
DEALS 1 ── N HISTORY　（版ごとの変更履歴）
DEALS 1 ── N FEEDBACK　（版ごとの確認と反応）
USERS 1 ── N HISTORY / FEEDBACK　（操作者）

AUDITはログインID・日時・成否を独立記録。詳細な項目と関係は03_設計.mdのMermaid図を参照。

画面遷移

ログイン ── 営業 ── 自分の案件一覧 ── 新規登録 ── 営業詳細
　　　　　　　　　　　　　└────────── 営業詳細 ⇄ 案件更新
　　　　└─ 部長 ── 全体ダッシュボード ⇄ 部長詳細 ── 既読・反応

保存・反応はサーバーに記録。営業が再更新すると、現在版の既読・反応は未確認に戻る。
