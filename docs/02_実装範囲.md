# 優先順位と実装範囲

要件定義書の1ヶ月計画と、本課題の短時間試作は別の計画である。課題の「実装開始2時間で一度動く」に合わせ、試作の実装予算を120分と仮定して絞った。工数は計画用見積であり実測工数ではない。

|機能|原要件|課題優先度|見積分|今回の実装|
|---|---|---|---:|---|
|F06 登録・終了|Must|P0|15|登録、受注・失注、終了一覧|
|F01 更新・履歴|Must|P0|20|前回値、変更履歴、競合検知|
|F03 部長一覧・集計|Must|P0|15|担当・ステージ絞り込み、確定額と見込み額|
|F04 要注意抽出|Must|P0|8|7日停滞、期日超過|
|F05 既読・反応|Must|P0|15|現在版の確認と3種類の反応、再更新で未確認|
|F08 最小ログイン・権限|Must|P0|10|営業・部長の2役割、サーバー側アクセス制御|
|F02 画面内期日通知|Must|P1|5|翌日までの件数表示のみ|
|24件のデータ・動作試験・修正|課題必須|P0|22|初期生成、HTTP・ブラウザー検証|
|キャプチャ・最低限README|課題必須|P0|10|3画面以上と起動手順|
|合計|||120|最初の動作版の目標予算|

詳細設計資料と提出用整理は実装予算とは別作業。2時間時点のチェックポイントは、最初にHTTP試験が通りローカル起動できた版とする。ただし開始時刻を自動記録しておらず、正確な2時間以内達成は保証しない。実行ログの時刻とGit履歴が残る範囲を証跡とする。

## セキュリティと制限

パスワードはソルト付きPBKDF2。HttpOnly/SameSite Cookie、CSRFトークン、送信元確認、サーバー側権限、SQLパラメーター化、表示文字列のエスケープ、版番号による競合検知を実装。ログイン5回失敗で5分ロック。ただしセッションと失敗回数はプロセス内であり再起動時に消える。HTTPS、永続的なアカウント停止、監査改ざん対策は未実装。接続先を127.0.0.1に固定し、架空データの課題デモに限定する。
