# ヒアリングと課題の整理

資料：要件定義書本文v0.2およびユーザー提供のAIクライアント会話。質問・応答の記録は確認できたが、15分という所要時間は未確認。以下の質問票は追加確認用に作成したもので、ヒアリング前に準備済みだったという主張ではない。

## 発言と本当の困りごとの切り分け

|依頼者の発言・状況|分析した困りごと|設計への反映|
|---|---|---|
|月末まで誰が何を進めているか分からない|問題に気づき支援する時期が遅れる|全体一覧、次のアクション、停滞・期日超過抽出|
|統一Excelは2ヶ月で使われなくなった|形式統一だけでは入力を続ける理由にならない|簡潔な更新と既読・反応の循環|
|営業3名は「誰も見ていない」「質問されたことがない」と回答|営業が入力の成果と支援を感じられない|部長確認済み、ワンタップ反応|
|承認待ちでは面倒で入力しなくなる|統制による入力停止が定着を阻害する|承認待ちなしで更新可能|
|週15分程度なら時間が取れる|部長の作業を増やしすぎると反応が止まる|要注意絞り込みと3種類の反応|

課題を1文で表す：営業が短時間で商談を更新し、部長が月末を待たずに状況を把握して支援の反応を返すことで、入力が続かない状態を改善する。

## 関係者の目的・懸念・価値

|関係者|目的|懸念|提供する価値|
|---|---|---|---|
|営業12名|簡単に報告し、商談を進める|二重入力、監視、書いても無反応|前回値入力、支援の反応、将来的な口頭報告削減|
|営業部長|進捗と見込みを把握し支援|確認作業の増加、再び利用停止|一覧、要注意抽出、ワンタップ反応|
|経営層|当月の受注見込み把握|数字の定義や精度の不一致|確定額と見込み額を分離|
|情報システム部|機密保護と保守可能な運用|基盤、社外接続、SSO、監査|本番移行前の確認事項を明文化|
|開発・運用担当|期間内に検証可能な成果を作る|機能膨張、運用担当未定|試作範囲の明示、再現可能な起動と検証|

## 追加15分の質問票

|時間|質問|決めたいこと|
|---|---|---|
|0〜3分|直近で発見が遅れて困った案件は何か。部長はいつ何を判断したかったか|優先する業務課題とデモ場面|
|3〜5分|営業はどの端末・タイミングで更新するか。今のExcelと二重入力をやめられるか|入力負荷と試行対象|
|5〜8分|ステージは5段階＋失注、行動は3択でよいか。未定金額・税区分はどうするか|A1と入力ルール|
|8〜10分|今月の見込みは予定月の単純合計でよいか。受注取消や再受注をどう数えるか|A3と集計定義|
|10〜12分|通知は何で、いつ送るか。週15分の確認時間と不在時の代理は誰か|通知と運用継続|
|12〜14分|情報システム部の担当者、社外接続・基盤の判断期限はいつか|A2・本番移行条件|
|14〜15分|この範囲で試作品を評価できるか。口頭報告を省く条件と承認者は誰か|受入と承認|

会話で方針合意は得られているが、税区分、ステージの最終一覧、見込みの厳密定義、通知手段、本番基盤は未確定のまま。試作品で仮定した値はREADMEに記載。
