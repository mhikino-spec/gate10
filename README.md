# Gate10 商談進捗管理システム

解決すべき課題：**営業が短時間で商談を更新し、部長が月末を待たずに状況を把握して支援の反応を返すことで、入力が続かない状態を改善する。**

ローカルで動く課題提出用Webアプリです。Python標準ライブラリ＋SQLiteで構成し、営業12名・部長1名・架空案件24件を初回起動時に作成します。既存のデータは起動時に初期化しません。

## 起動

Python 3.10以上をインストールしたPCで、このREADMEのあるフォルダーを開いて実行します。追加パッケージは不要です。

```powershell
python app.py
```

Windowsで `python` が使えない場合は `py app.py`。ブラウザーで http://127.0.0.1:8810/ を開きます。終了はターミナルで Ctrl+C。別ポート・別データで動かす場合は `python app.py --port 8811 --db data/another.sqlite3`。

|役割|ID|パスワード|
|---|---|---|
|営業12名|sales01〜sales12|Gate10Demo1234|
|部長|manager|Gate10Demo1234|

デモ専用アカウントです。実データを投入せず、インターネットに公開しないでください。データは `data/gate10.sqlite3` に保存し、Git管理から除外します。

## デモ手順 約5分

1. sales01でログイン。自分の案件・期日の通知・部長の反応を確認する。
2. 「新規案件を登録」で顧客名、案件名、ステージ、アクション、期日、金額を入力して保存する。
3. 詳細の「案件を更新」でステージやメモを変更。履歴に変更前後が記録されることを確認する。
4. ログアウトしmanagerでログイン。全体一覧、担当者・ステージ絞り込み、見込み額、要注意案件を確認する。
5. 登録した案件を開き「同行しようか」を押す。
6. sales01で再ログインし、既読と反応を確認する。再更新すると未確認に戻る。
7. ステージを受注または失注に変更。一覧の「終了を含む」で終了案件と履歴を確認する。

## 要件との差分と仮定

参照元ファイル名は「商談進捗管理システム 要件定義書 v0.1.docx」ですが、本文は v0.2・合意前です。追加で提供されたAIクライアントとの会話をヒアリング記録として参照しました。最後の「これで進めてみてくれ」は検討方針への合意として扱い、完成品の正式承認としません。

- 商談ステージは初回訪問・提案中・見積提出済み・内諾・受注・失注。次のアクションは訪問・見積送付・電話の3択。
- 金額は税抜円の整数を仮採用。第7章の必須指定と第11章の未定許可の矛盾は、未定を空欄で保存する例外を優先。未定を0円に変換しません。
- 見込み額は受注予定日が当月かつ進行中かつ金額がある案件を単純合算。確度加重なし。確定額は現在受注状態で、受注へ変更した日が当月の案件を合算。受注から進行中に戻したら確定額から除外し、再受注時は再受注日を用います。
- 期日超過は進行中で期日が今日より前の案件。「更新があれば超過解消」にはせず、期日の変更または終了で解除します。過去の期日を残した更新でも支援対象に残すための仮定です。
- 停滞は最終更新から168時間以上。変更なしの保存も活動確認とします。日時は日本時間、メモは140文字。
- 通知はログイン中の画面内表示。営業一覧には明日までの期日の件数を表示。外部通知・自動配信は未実装です。
- 部長画面への反映は次の画面表示または「最新の状況に更新」の操作時。リアルタイムの自動再取得は未実装です。
- 同一顧客名・案件名の完全一致は登録を拒否。重複警告後の強行登録・統合・表記ゆれ検出は未実装です。
- 本番向けSSO/MFA/管理者画面・担当替え・通知基盤・運用監視は今回の対象外です。理由と工数は実装範囲を参照。

## テスト

```powershell
python -m unittest discover -s tests -v
```

テストは一時DBを使い、提出者のデータを変更しません。登録→更新→既読→反応→再更新、他営業のアクセス拒否、CSRF、入力検証、競合、重複、ログイン失敗ロック、停滞境界、初期データの非破壊を確認します。

ブラウザー検証 `tests/browser.cjs` はNode.js、Playwright、Microsoft Edgeと起動済みサーバーが必要です。再実行すると検証案件を1件追加し、キャプチャを更新します。通常のアプリ起動にこれらは不要です。

30秒更新・週15分・13名同時利用・4Gで3秒・2ヶ月の継続利用・稼働率は利用者による実測未実施です。動作試験合格と業務KPI達成は分けて評価してください。
